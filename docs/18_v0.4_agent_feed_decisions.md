# v0.4 Agent Feed decisions

- Accepted: generic monitoring protocol should be reusable across projects.
- Accepted: Agent Feed is a separate project, repository/deployable, and production data store.
- Accepted: Rewards Optimizer references a pinned protocol and implements a consumer adapter only.
- Accepted: begin-run / submit-batch / complete-run distinguishes successful zero-finding runs from failure.
- Accepted: submitted evidence is not canonical evidence.
- Accepted: Supabase Queues/outbox support durable delivery; Realtime is optional UX.
- Accepted with capability gate: ChatGPT Scheduled Tasks are useful sentinels, but no webhook integration is assumed.
- Rejected: direct shared database access between Agent Feed and the Rewards Optimizer.
- Rejected: generic finding-to-reward-rule mutation.

## v0.4.1 sequencing clarification

Agent Feed remains a separate project because other consumers are planned, but only the thin protocol/persistence/liveness path needed by Rewards is authorized before the first working recommendation and maintenance rehearsal. Broad SDK, adapter, MCP, dashboard, Realtime, and second-production-project work is deferred.
